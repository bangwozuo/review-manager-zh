# 安抚话术生成

为每条差评写 30-80 字的公开回复：引用原文细节、给真实方案、不超出补偿授权。
回复真正写给未来进店的买家看，其次才是差评买家本人。

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_ecom_03_sk03` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 评价运营官 |
| 能力族 | 文案生成型 · 差评回复 |
| 复杂度 | `M` |
| 阶段 | `P0` |
| 复用度 | ★★★★★（appease-compensation-flow 核心步骤） |
| 资产形态 | 纯提示词（无运行时依赖） |

## 能力描述

1. **回复四件套**（30-80 字硬性）：认领问题（引原文细节）→ 说明原因（不甩锅快递/供应商）→ 给方案（具体动作+时间）→ 留通道（私信/客服入口）
2. **前置三判断**：根因是否已定 / 是否疑似恶意差评（是则转申诉不缠辩）/ 补偿授权边界
3. **处置 L1-L5 分级**：L1 3 星期望差不补偿（0 元）→ L2 物流描述不符补发或 5-10 元券（≤ 客单价 30%）→ L3 工艺质量补发或退 30%-50%（≤ 60%）→ L4 质量安全全额退款+电话+留证 → L5 涉诉词（12315/曝光）停用模板转人工 2 小时介入
4. **追评特则**：引用追评内容而非首评，写清首评到追评之间商家履约时间线；已履约仍差评的用事实时间线平实回应
5. **防职业索赔**：同一买家 30 天内第二次 L3 以上补偿升级人工审核

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `reviews` | array | ✅ | [{star, text, has_image, is_followup}]，差评原文 |
| `root_cause` | string | ⬜ | 已判定的根因标签（缺省由模型按原文判断并给依据） |
| `policy` | string | ✅ | 可用的补偿方式与边界，如「补发+无门槛券 ≤10 元」；无授权则只给文案 |

## 输出规格

- `replies`：回复文案表（评价要点 / 情形分级 / 文案与字数 / 处置动作）
- `root_judgment`：根因判断（依据引原文）
- `remedies`：补救建议（每条注明是否在授权内 / 是否需人工确认）
- `pending`：存疑项（根因不清 / 疑似恶意 / 授权外请求）

## 使用步骤

### 方式一：纯提示词（最快）

1. 把 `prompt.txt` 全文粘贴为系统提示词
2. 提供差评原文 + 处置口径（policy）
3. 得到回复文案表 + 根因判断 + 补救建议；发布前人工确认

### 方式二：在主流平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |

## 边界（不做的事）

- ❌ 不写无细节模板腔（「亲，抱歉给您带来不好的体验」）
- ❌ 不用利诱换改评（返现/赠品换好评/要求删差评），违反《反不正当竞争法》第 8 条
- ❌ 不在公开回复中承认未经核实的质量安全问题（留证前写「正在核实」）
- ❌ 不编造补偿已发生的事实；不与买家公开缠辩（超两轮转私信人工）

## 调用示例

**输入**（`examples/input.json`）：物流慢的商品正面评价 1 条，policy「优惠券最高 20 元」。

**输出**（`examples/output.md`）：58 字回复（认领物流延迟 + 说明高峰期原因 + 15 元券方案 + 留客服通道），根因判「物流延迟 · 轻度」，处置在 20 元授权内；附物流反馈、时效预期管理、轻量补偿标准化三条补救建议。

## 合规声明

- 本技能输出为 **AI 辅助生成内容**，每条回复发布前必须经人工确认
- 回复公开可见，遵守平台评价回复规范（不留联系方式、不引导站外交易）
- L4/L5（质量安全、涉诉）案件全程人工处理，本技能仅提供留证与口径建议
