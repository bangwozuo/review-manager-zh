# 使用示例

## 示例 1：评分未达标的专项治理判定

**输入**：`examples/input.json`（悦己家居旗舰店，京东：评分 4.62、差评率 4.6%、回复率 94%、物流根因 9 条）。

**输出**（脚本实跑）：核心结论「本周评分 4.62，低于 4.7 达标线，须专项治理。首要根因『物流问题』占差评 56%」；指标对照 6 项中 5 项未达标（标红）；改进 3 项自动带数字目标。

## 示例 2：噪声与趋势区分

**输入**：`score_trend: [4.71, 4.70, 4.68, 4.65, 4.60, 4.58, 4.62]`。

**输出**：走势图呈现下滑-回升；若给连续 3 天同向下滑序列 → 告警「判趋势恶化非噪声」；变化 ≤ 2 个百分点的指标标注「噪声」，不下结论。

## 示例 3：数据缺失的段位处理

**输入**：只给本周指标，不给 `last_metrics`。

**输出**：上周列显示「—」，不估算、不编造对比；报告结论退化为单周判定，缺口写入「数据缺失」。

## 示例 4：改进项硬约束

**输入**：根因分布仅 1 类（物流 16 条）。

**输出**：改进项按实际根因数生成（1 项），不凑满 3 项；每项必带数字目标（发货 P90 ≤ 48 小时、漏发率 < 0.3%）与责任人占位（周会指派）——拒绝「加强管理」空话。详见 `examples/output.md`。
