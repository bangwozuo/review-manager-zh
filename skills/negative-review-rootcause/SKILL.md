# 差评根因分类

把 1-3 星差评归到六类根因，输出「首要治理专项 + 带数字目标的改进项」。

**词表规则树归因与加权统计由 `scripts/rootcause.py` 计算，数值以脚本输出为准，不要自己算。**

## 元信息

| 字段 | 值 |
|------|-----|

## 能力描述

1. **六类根因规则树**：质量安全（最高优先级，命中即当日处理）→ 工艺 → 物流 → 服务 → 描述不符 → 性价比 → 兜底期望差；连带表述拆主次标签（「物流慢导致坏果」= 物流主 + 质量次）
2. **加权统计**：追评权重 ×2（收货后补充评价更可信）；带图差评单独计「图证数」
3. **治理阈值**：单一根因 > 40% 列首要治理专项；质量安全 > 10% 当日下架自查；样本 < 10 条只列明细不给占比
4. **改进项数字目标**：破损率 < 0.5%、发货 P90 ≤ 48 小时、退款响应 ≤ 2 小时——拒绝「加强管理」空话

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `shop` | string | ✅ | 店铺名 |
| `platform` | string | ✅ | 平台 |
| `period` | string | ⬜ | 统计周期 |
| `negatives` | array | ✅ | [{star, text, has_image, is_followup}]，1-3 星差评与追评差评 |

## 输出规格

| 字段 | 类型 | 说明 |
|------|------|------|
| `summary` | object | 差评总数 / 首要根因及占比 / 质量安全占比 / 治理判定 |
| `distribution` | array | 六类根因加权分布 + 对应治理动作 |
| `detail` | array | 逐条归因明细（主根因/次标签/权重/图证） |
| 产物 | 文件 | `out/差评根因分类.xlsx`、`out/根因分布.png`、`out/rootcause.json` |

## 使用步骤

### 方式一：纯提示词（最快）

1. 把 `prompt.txt` 全文粘贴为系统提示词
2. 提供差评列表（星级/文字/是否带图/是否追评）
3. 得到六类根因分布 + 首要治理判定 + 改进项

### 方式二：带脚本（规则树精确归因 + 产出 Excel）

```bash
python3 <SKILL_DIR>/scripts/rootcause.py --input input.json --outdir out
python3 <SKILL_DIR>/scripts/rootcause.py --demo
```

产物：

| 文件 | 内容 |
|---|---|
| `out/差评根因分类.xlsx` | 分布统计（安全类标红）/ 根因明细 / 汇总 |
| `out/根因分布.png` | 根因加权分布柱状图 |
| `out/rootcause.json` | 机器可读结果，供工作流读取 |

**分工**：脚本做词表归因与加权统计；模型做连带因果拆解、批次交叉验证、误判复核。

## 边界（不做的事）

- ❌ 不把「不合口味」归为质量问题（期望差单列，否则误伤品控方向）
- ❌ 样本 < 10 条不给占比结论，只逐条处置
- ❌ 疑似刷手/恶意差评不进根因统计，转 dispute-evidence-pack-flow 申诉
- ❌ 不给无数字目标的空建议；不编造差评数据

## 调用示例

**输入**（`examples/input.json`）：果真甜生鲜旗舰店（拼多多），2026-09-22 ~ 09-28 共 12 条差评（含 3 条带图、2 条追评）。

**输出**（脚本实跑，退出码 0）：首要根因「期望差(主观)」占 36%；**质量安全类占 14%（> 10%）→ 触发当日下架留证批次自查**。分布 Top3：期望差 / 质量安全 / 物流。产物三件：Excel 分布统计、根因柱状图、JSON。
