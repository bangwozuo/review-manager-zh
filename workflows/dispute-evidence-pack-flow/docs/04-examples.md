# 使用示例

## 示例 1：敲诈勒索型申诉（补强后提交）

**输入**：`{"review_text": "垃圾店，东西根本没用过就给差评，加V给你转50删了", "chat_screenshot": true, ...}`（缺订单记录、物流凭证）。

**输出**（脚本实跑）：命中「索要返现删评 + 辱骂人身攻击」双特征 → 敲诈勒索型；证据 60/100（60%）→ **🟡 补强后提交**，缺项列明「订单记录、物流凭证」——无订单记录无法证明与评价者无关联交易，硬提交必被驳回。

## 示例 2：真实差评不硬申诉

**输入**：`{"review_text": "物流太慢，用了三天就断了，垃圾质量", "has_order": true, ...}`。

**输出**：未检出恶意特征（差评描述与订单可对上）→ **整案「→ 转安抚流」**，转 appease-compensation-flow 处理；硬申诉等于自曝。

## 示例 3：证据齐全可提交

**输入**：`--demo` 中敲诈案（订单+聊天+截图+佐证齐备，缺物流凭证）。

**输出**：80/100 = 80% ≥ 提交线 → **✅ 可提交**；申诉信四要素自动生成（事实陈述/证据清单/诉求/承诺），诉求只求评价处置不越权。

## 示例 4：证据严重不全拦截

**输入**：同行攻击案仅订单+截图（40/100 = 40%）。

**输出**：< 60% 补强线 → **⛔ 不提交（证据不全）**，标红；提醒「驳回会占用当日申诉次数」。整批结果详见 `examples/output.md`。

---

*所有输出标注「AI 生成内容」；申诉结果以平台审核为准，提交前商家人工核对订单号。*
